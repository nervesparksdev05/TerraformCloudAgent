## Security Rules (CRITICAL – NEVER VIOLATE)

### Forbidden
- ❌ `provisioner "local-exec"` or `provisioner "remote-exec"` – NEVER use
- ❌ `null_resource` – NEVER use
- ❌ Hard-coded credentials, API keys, or service account keys in any file
- ❌ `0.0.0.0/0` for SSH (port 22) ingress – use IAP range (35.235.240.0/20) or a configurable variable with NO default of 0.0.0.0/0
- ❌ Hard-coded image names/families – use `data "google_compute_image"` with family filter
- ❌ Generating service account keys by default – prefer Workload Identity and impersonation

### Required
- ✅ Encryption at rest: CMEK option for Cloud Storage, Cloud SQL, GKE, Pub/Sub (with Google-managed as default)
- ✅ Encryption in transit: SSL policies on load balancers, require_ssl on Cloud SQL
- ✅ `sensitive = true` on all password/secret/key variables and outputs
- ✅ Least-privilege IAM: custom roles with minimum permissions, dedicated service accounts per resource
- ✅ Firewall rules: deny-all base, explicit allow rules with target tags and source ranges
- ✅ Shielded VM on all Compute Engine instances
- ✅ OS Login enabled (`enable-oslogin = "TRUE"` in instance metadata)
- ✅ `deletion_protection = true` by default for databases and critical resources (variable to override)
- ✅ Private Google Access on all subnets
- ✅ VPC flow logs enabled on subnets

## Naming & Labeling Conventions

Resource names MUST use this pattern:
```hcl
name = "${var.project_name}-${var.environment}-<resource-descriptor>"
```
Example: `"${var.project_name}-${var.environment}-web-vm"`

GCP resource names have constraints:
- Must be lowercase
- Must start with a letter
- Can contain letters, numbers, and hyphens
- Max 63 characters for most resources

Use `locals` for computed values:

```hcl
  common_labels = {
    environment = var.environment

  }
}
```
