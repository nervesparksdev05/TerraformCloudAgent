## Provider & Version Pinning
```hcl
terraform {
  required_version = ">= 1.5"
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
    tls = {
      source  = "hashicorp/tls"
      version = "~> 4.0"
    }
    archive = {
      source  = "hashicorp/archive"
      version = "~> 2.0"
    }
  }
}

provider "aws" {
  region = var.aws_region
  default_tags {
    tags = {
      Environment = var.environment
      Project     = var.project_name
      ManagedBy   = "terraform"
    }
  }
}
```
- Include `tls` provider ONLY when generating SSH keys (EC2).
- Include `archive` provider ONLY when packaging Lambda code.
- Always use `default_tags` on the AWS provider for consistent tagging.

## Security Rules (CRITICAL – NEVER VIOLATE)

### Forbidden
- ❌ `provisioner "local-exec"` or `provisioner "remote-exec"` – NEVER use
- ❌ `null_resource` – NEVER use
- ❌ Hard-coded credentials, access keys, or secrets in any file
- ❌ `0.0.0.0/0` for SSH (port 22) or RDP (port 3389) ingress – use a variable with NO default or a restrictive CIDR
- ❌ Inline JSON strings for IAM policies – use `data "aws_iam_policy_document"`
- ❌ Hard-coded AMI IDs – use `data "aws_ami"` with filters

### Required
- ✅ Encryption at rest for: S3, RDS, EBS, DynamoDB, SQS, SNS, CloudWatch Logs, EKS secrets
- ✅ Encryption in transit: enforce SSL on S3 bucket policies, HTTPS listeners, TLS for RDS
- ✅ `sensitive = true` on all password/secret/key variables and outputs
- ✅ Least-privilege IAM: only grant permissions actually needed
- ✅ Security groups: deny by default, allow only required ports from specific CIDRs
- ✅ IMDSv2 required on all EC2 instances
- ✅ `deletion_protection` = true by default for databases and load balancers (variable to override)

## variables.tf Requirements

Every `variables.tf` MUST include these baseline variables:
```hcl
variable "aws_region" {
  description = "AWS region for resource deployment"
  type        = string
  default     = "us-east-1"
}

variable "environment" {
  description = "Deployment environment (dev, staging, prod)"
  type        = string
  default     = "dev"
  validation {
    condition     = contains(["dev", "staging", "prod"], var.environment)
    error_message = "Environment must be dev, staging, or prod."
  }
}

variable "project_name" {
  description = "Project name used for resource naming and tagging"
  type        = string
  default     = "myproject"
}
```

Additional rules:
- ALL variables used in main.tf MUST be declared
- Use `type` (string, number, bool, list, map, object) on every variable
- Include `description` on every variable
- Provide sensible `default` values where safe (never default secrets)
- Use `validation` blocks for enums and constrained values
- Use `sensitive = true` for passwords, keys, tokens
- Group variables logically with comment headers
